# 预加载功能说明

最后更新：2026-07-07

## 当前结论

预加载只保留真实执行的资源阶段，避免显示虚假的 100%。当前流程为：

1. 静态资源预加载完成：50%。
2. PDF 字体预加载完成：100%。

旧的表单页面预加载和脚本 / 样式预加载只是空实现，已经移除。

## 用户入口

- 登录后进入 Dashboard 会自动触发预加载。
- 预加载进行中，用户菜单显示「预加载中 X%」和当前阶段。
- 预加载完成后，该菜单项直接隐藏，不再展示「资源已预加载 (100%)」。原因：完成后权限哈希未变化，再次点击 `preloadAllResources` 会被 `checkPermissionsChanged` 直接跳过，按钮已无实际功能，保留完成态文案只会占用菜单空间且无法交互，因此改为完成后整行消失（`src/components/layout/AppUserMenu.tsx`）。

## 技术入口

- 核心实现：`src/utils/preloadUtils.ts`
- UI 入口：用户菜单相关组件
- 字体缓存：`src/utils/fontCache.ts`
- 图片缓存：`src/utils/imageCache.ts`

## 进度口径

| 阶段 | 进度 | 说明 |
|------|------|------|
| 静态资源 | 50% | 预加载 Logo、头图等实际静态资源 |
| PDF 字体 | 100% | 预加载 Noto Sans SC 字体，保障 PDF 生成 |

如果后续重新加入表单页面、脚本或样式预加载，必须先实现真实加载逻辑，再把阶段加入进度计算。

## 缓存策略

- 预加载完成时间写入 localStorage。
- 24 小时内认为资源已预加载，避免重复执行。
- 单个资源失败不应阻断整个应用使用，但需要在开发环境便于排查。

## 维护注意

1. 不要新增只更新百分比、不做实际工作的阶段。
2. 新增 PDF 字体或头图资源时，同步检查预加载资源列表。
3. 构建时 `npm run build` 会重新生成 `src/lib/embedded-resources.ts`，不要手工编辑该文件。
